ROA 전시용 21-DOF 모션 시스템 전체 실행 가이드
================================================

1. 구성 개요
------------

이 workspace는 기존 보행용 ~/colcon_ws와 분리된 전시 전용 환경이다.

  - robstride_hardware_interface: 실제 모터 제어
  - roa_motion_player: 게임패드 입력 및 모션 재생
  - roa_interfaces: MotorCommandArray 등 ROS 메시지
  - roa_exhibition_bringup: 전시용 21-DOF, 100 Hz 설정과 launch 파일

Hardware interface와 motion player는 모두 100 Hz로 동작한다.
Motion player는 /hardware_interface/command를 발행하고 hardware interface는
동일한 명령을 실제 RobStride 모터에 전달한다.


2. 최초 다운로드와 submodule 준비
---------------------------------

새로 clone하는 경우:

  git clone --recurse-submodules https://github.com/WJJJ2004/roa_exhibition_ws.git
  cd roa_exhibition_ws
  git submodule update --init --recursive

이미 clone한 workspace를 업데이트하는 경우:

  cd roa_exhibition_ws
  git pull --ff-only
  git submodule update --init --remote

주의:

  - 전시 중에는 검증되지 않은 원격 변경을 바로 받지 않는다.
  - 업데이트 후에는 반드시 다시 빌드하고 RViz 또는 모터 비활성 상태에서 확인한다.
  - 보행용 workspace와 전시용 workspace를 같은 터미널에서 source하지 않는다.


3. 빌드
-------

보행용 ~/colcon_ws를 source하지 않은 새 터미널을 연다.

  cd roa_exhibition_ws
  ./build_exhibition.sh

빌드가 끝나면 다음과 같은 결과가 보여야 한다.

  Summary: 4 packages finished

빌드 대상:

  - roa_interfaces
  - robstride_hardware_interface
  - roa_motion_player
  - roa_exhibition_bringup


4. 터미널 환경 설정
-------------------

전시 시스템을 실행하는 모든 터미널에서 다음을 실행한다.

  cd roa_exhibition_ws
  source setup_exhibition.bash

패키지 경로 확인:

  ros2 pkg prefix robstride_hardware_interface
  ros2 pkg prefix roa_motion_player
  ros2 pkg prefix roa_exhibition_bringup

세 명령 모두 아래 workspace의 install 경로를 출력해야 한다.

  <현재 clone한 roa_exhibition_ws 경로>/install/...

~/colcon_ws/install 경로가 나오면 터미널을 닫고 새 터미널에서 다시 시작한다.


5. 로봇 및 CAN 사전 점검
-----------------------

5.1 물리적 점검

  - 로봇을 넘어지지 않도록 고정한다.
  - 비상 정지 수단을 바로 사용할 수 있게 준비한다.
  - 작업자와 관람객이 팔의 동작 범위 밖에 있는지 확인한다.
  - 전원, CAN 어댑터, 게임패드 연결 상태를 확인한다.
  - 처음 시험할 때는 로봇을 지지하고 낮은 위험 상태에서 수행한다.

5.2 CAN 인터페이스 확인

  ip -br link show can_right_leg
  ip -br link show can_left_leg
  ip -br link show can_right_arm
  ip -br link show can_left_arm

네 인터페이스가 모두 존재해야 한다.

필요한 경우 각 인터페이스를 1 Mbps, TX queue 4096으로 설정한다.

  for iface in can_right_leg can_left_leg can_right_arm can_left_arm; do
    sudo ip link set "$iface" down 2>/dev/null || true
    sudo ip link set "$iface" type can bitrate 1000000 loopback off
    sudo ip link set "$iface" txqueuelen 4096
    sudo ip link set "$iface" up
  done

설정 확인:

  ip -details link show can_right_leg
  ip -details link show can_left_leg
  ip -details link show can_right_arm
  ip -details link show can_left_arm


6. 실제 하드웨어 실행 순서
-------------------------

안전을 위해 아래 순서를 지킨다. Motion player를 먼저 configure 이후에 실행하여
hardware interface가 activate되기 전에 초기 idle command를 받을 수 있게 한다.

6.1 터미널 1: Hardware interface 노드 실행

  cd roa_exhibition_ws
  source setup_exhibition.bash
  ros2 launch roa_exhibition_bringup hardware.launch.py

이 launch는 다음 설정을 사용한다.

  src/roa_exhibition_bringup/config/hardware_100hz.yaml

제어 대상 버스:

  - can_right_leg: 9, 11, 13, 15, 17, 19, 21
  - can_left_leg: 10, 12, 14, 16, 18, 20
  - can_right_arm: 22, 23, 1, 3, 5, 7
  - can_left_arm: 0, 2, 4, 6

6.2 터미널 2: Lifecycle configure

  cd roa_exhibition_ws
  source setup_exhibition.bash
  ros2 lifecycle set /hardware_interface_node configure
  ros2 lifecycle get /hardware_interface_node

상태가 inactive인지 확인한다. 이 단계에서는 모터를 activate하지 않는다.

6.3 터미널 3: Motion player 실행

  cd roa_exhibition_ws
  source setup_exhibition.bash
  ros2 launch roa_exhibition_bringup motion_hw.launch.py

Motion player는 100 Hz로 /hardware_interface/command를 발행한다. 그러나
/walk_initialized=true가 수신되기 전까지 WAIT_HW 상태에서 idle command만
발행하고 게임패드 모션은 실행하지 않는다.

6.4 터미널 2: Hardware interface activate

로봇 주변이 안전하고 터미널 1과 3에 오류가 없는 것을 확인한 후 실행한다.

  ros2 lifecycle set /hardware_interface_node activate
  ros2 lifecycle get /hardware_interface_node

상태가 active인지 확인한다. Hardware interface의 초기 feedback 검증, 모터 enable,
초기 자세 보간이 정상 완료되면 /walk_initialized=true가 발행된다. 그 후 Motion
player는 startup delay를 거쳐 IDLE 상태로 진입한다.

다음 로그가 나타날 때까지 게임패드 버튼을 누르지 않는다.

  FSM: IDLE; accepting gamepad buttons


7. 게임패드 모션 실행
--------------------

기본 Logitech 게임패드 버튼 매핑:

  A: 오른팔 인사
  X: 왼팔 인사
  Y: 오른팔 경례
  B: 오른팔 악수

입력은 IDLE 상태에서만 받는다. 동작 중 버튼 입력은 무시된다.

FSM 순서:

  IDLE
    -> INTERPOLATE_TO_MOTION (1초)
    -> MOTION_PLAY
    -> INTERPOLATE_TO_IDLE (1초)
    -> IDLE

악수 동작에서는 오른팔 Kp/Kd가 기본 arm gain의 50%로 낮아지며, 진입과
복귀 보간 구간에서 gain도 함께 부드럽게 변경된다.

주의:

  - 보행 controller 등 다른 노드가 /hardware_interface/command를 동시에 발행하면
    안 된다.
  - 한 모션이 끝나고 IDLE 로그가 나온 뒤 다음 버튼을 누른다.
  - 게임패드가 인식되지 않으면 /dev/input/event* 권한과 USB 연결을 확인한다.


8. 상태 확인 명령
-----------------

Lifecycle 상태:

  ros2 lifecycle get /hardware_interface_node

초기화 완료 flag:

  ros2 topic echo /walk_initialized

Hardware command 발행 주기:

  ros2 topic hz /hardware_interface/command

Hardware feedback 주기:

  ros2 topic hz /hardware_interface/state

Command publisher 확인:

  ros2 topic info /hardware_interface/command --verbose

정상 상태에서는 command publisher가 roa_motion_player 하나인지 확인한다.


9. 정상 종료
------------

9.1 터미널 2에서 먼저 모터를 deactivate한다.

  ros2 lifecycle set /hardware_interface_node deactivate

9.2 모터 disable 로그를 확인한다.

9.3 터미널 3의 Motion player를 Ctrl+C로 종료한다.

9.4 터미널 1의 Hardware interface를 Ctrl+C로 종료한다.

로봇이 활성화된 상태에서 터미널 프로세스만 먼저 강제 종료하지 않는다.


10. 비상 정지
-------------

즉시 motor disable을 요청하려면 다음을 실행한다.

  ros2 topic pub --once /hardware_interface/etop std_msgs/msg/Bool "{data: false}"

E-stop 또는 FROZEN 상태는 latched safety 상태이므로 true 메시지로 바로 복구되지
않는다. 원인을 제거한 후 lifecycle deactivate -> activate를 새로 수행해야 한다.


11. Feedback stale/FROZEN 복구
------------------------------

다음과 같은 로그가 발생하면 hardware command는 무시된다.

  [Frozen] [Safety] Feedback stale ...
  Upper commands are ignored; lifecycle reactivation is required.

복구 절차:

  1) 게임패드에서 손을 떼고 로봇 주변을 비운다.
  2) 어떤 CAN 버스와 motor ID에서 지연됐는지 로그를 확인한다.
  3) CAN 연결, 전원, bus 상태와 error counter를 확인한다.
  4) lifecycle을 deactivate한다.
  5) 원인이 제거된 뒤 activate한다.

명령:

  ros2 lifecycle set /hardware_interface_node deactivate
  ip -details -statistics link show can_right_arm
  ip -details -statistics link show can_left_arm
  ip -details -statistics link show can_right_leg
  ip -details -statistics link show can_left_leg
  ros2 lifecycle set /hardware_interface_node activate

activate 후 /walk_initialized=true와 Motion player의 IDLE 로그를 다시 확인한다.


12. RViz 단독 점검
------------------

실제 Hardware interface를 실행하지 않고 모션과 URDF만 확인할 경우 새 터미널에서:

  cd roa_exhibition_ws
  source setup_exhibition.bash
  ros2 launch roa_motion_player motion_rviz.launch.py

RViz 모드는 실제 모터를 enable하지 않는다. Motion player가 만든 동일한
/hardware_interface/command를 JointState adapter가 변환하여 시각화한다.


13. 주요 설정 파일
------------------

전시용 Hardware interface 100 Hz 및 CAN 구성:

  src/roa_exhibition_bringup/config/hardware_100hz.yaml

전시용 Motion player 100 Hz, startup delay, gamepad 설정:

  src/roa_exhibition_bringup/config/motion_player_100hz.yaml

모션 및 버튼 매핑:

  src/roa_motion_player/config/motion_catalog.yaml

Gain profile:

  src/roa_motion_player/config/gain_profiles.yaml

Idle 자세:

  src/roa_motion_player/motions/idle_pose.yaml


14. 설정 변경 후 반영
--------------------

roa_exhibition_bringup 설정을 변경한 후:

  cd roa_exhibition_ws
  ./build_exhibition.sh
  source setup_exhibition.bash

launch 중인 노드는 기존 설정을 계속 사용하므로 변경 후 노드를 다시 시작한다.
보행용 ~/colcon_ws/install/setup.bash를 source한 터미널은 재사용하지 않는다.


15. 전시 시작 전 최종 체크리스트
--------------------------------

  [ ] 전시용 workspace만 source했다.
  [ ] 네 CAN 인터페이스가 모두 UP이다.
  [ ] 로봇과 팔의 동작 영역이 확보됐다.
  [ ] Hardware interface configure가 성공했다.
  [ ] Motion player가 실행되어 idle command를 발행한다.
  [ ] Hardware interface activate가 성공했다.
  [ ] /walk_initialized=true를 확인했다.
  [ ] FSM IDLE 로그를 확인했다.
  [ ] /hardware_interface/command publisher가 하나뿐이다.
  [ ] 비상 정지 명령과 물리적 전원 차단 수단을 준비했다.
